FTMO public no-login evidence acquisition v1
Frozen 2026-09-11 before implementation or an archived acquisition run. Infrastructure study; no alpha hypothesis, model fit, performance claim, account authentication or execution authorization.

PURPOSE AND BOUNDARY
Acquire the current public FTMO symbol specification for US500.cash without an FTMO account login, preserve the exact response and provenance, and convert the available fields into a reviewable evidence record. The only network source is the official HTTPS endpoint https://ftmo.com/wp-json/ftmo/symbols exposed by https://ftmo.com/en/symbols/. No credentials, cookies, account identifiers, MetaTrader terminal access, orders, EA changes, model fitting or strategy tests are allowed. Public contract data may reduce the missing-data set but can never authenticate the owner's account or represent executed quotes/fills.

ARTIFACTS AND INTERFACE
evaluate/ftmo_public_evidence_v1.py uses the Python standard library. Its online CLI takes --output-dir NEW_PATH, optional --as-of ISO8601_UTC, and defaults to the exact allowlisted endpoint and symbol US500.cash. A test-only/offline parsing interface accepts supplied bytes plus explicit provenance but can never qualify official retrieval. The output directory is immutable: an existing path is refused. The actual run writes raw_symbols_response.json, its SHA-256, retrieval_metadata.json, public_symbol_evidence.json and audit.json. HTTP redirects must end on an HTTPS ftmo.com host, status must be 200, media type must be JSON, and response size is bounded. Retrieval time, requested/final URL, response headers needed for provenance and SHA-256 are recorded. Secret-like response keys cause refusal before archival.

DATA DEFINITIONS
The response must be a JSON object containing data.symbols, data.tradingHours and data.platformTimeOffset.UTC. The selected symbol must match code US500.cash exactly and uniquely. Preserve, without unit conversion, the public symbol id, asset class, region, code/display code, name, contract size, margin percent/currency, profit currency, calculation modes, swap long/short/type, commission/type, active interval, Standard and Swing leverage, digits, commission helper fields, maximum trade and total volume, expiration flag and ticker group. Preserve all tradingHours rows whose symbolId equals the selected id. Times parse as aware ISO-8601 instants. Public trading hours are schedule observations for the retrieved week, not uninterrupted historical availability.

CURRENTNESS AND CONSISTENCY
The response is current for this artifact only when retrieval is no later than --as-of, no selected interval is malformed, at least one selected interval contains the UTC date of --as-of or begins/ends within seven calendar days of it, and the selected contract is active at --as-of. Numeric values must be finite; contract size, margin percent, both leverages and digits must be positive; commission and volume limits must be nonnegative; the selected symbol id/code in trading-hour rows must agree with the symbol. Null fields are preserved and reported. No undocumented default, legacy broker value or inferred MT5 point value may fill a missing field.

INTERPRETATION
The public record may support the public contract name, contract size, currencies, leverage, margin percentage, displayed swap rate/type, commission and current weekly trading hours at the retrieval time. Swap values stay in their published unit. Converting a swap value to account-currency financing requires the account's actual tick size/tick value and rollover multiplier. Digits do not prove tick size. maxTradeVolume does not prove minimum volume or volume step. A zero commission field does not prove zero spread, slippage or all-in execution cost.

PREDECLARED GATES
P-I1: This SPEC exists before implementation; GATE is a verbatim extraction of every P- line before the implementation script, tests or archived acquisition run; existing SPEC/GATE/REPORT files and frozen EAs remain untouched.
P-S1: An online run retrieves HTTP 200 JSON from the allowlisted official HTTPS FTMO endpoint, ends on an HTTPS ftmo.com host, records requested/final URL and UTC retrieval time, archives the exact bounded response bytes, and records a matching SHA-256; any violation is FAIL and no response is archived when secret-like keys are present.
P-S2: The response contains exactly one active US500.cash record, required public fields and internally valid finite values, with symbol id/code-consistent trading-hour rows and parseable aware times; malformed, contradictory or duplicate data is FAIL, while an unavailable nullable public field is reported without fabrication.
P-S3: The selected contract is active at --as-of and its published trading-hour intervals are current within the declared seven-day rule; stale or future-dated retrieval, inactive contract or stale schedule is FAIL for this artifact.
P-C1: The generated evidence preserves the official values and units without inferred tick economics, includes every selected trading-hour row, and separately enumerates facts supported by the public response and fields still required from account/MT5 or observed execution evidence.
P-L1: Account fingerprint, exact assigned server, current balance/equity/phase, tick size/value, minimum/step volume, stops/freeze levels, filling modes, rollover multipliers, bid/ask history, spread distribution, fills/slippage and independent reconciliation remain INCOMPLETE unless later supplied by authentic separate evidence; public data never satisfies FTMO qualification gates G-D1, G-D3 or G-D4 by itself.
P-F1: REPORT lists every gate and exact run evidence. Overall is PARTIAL only when P-I1 through P-C1 pass and P-L1 remains explicitly INCOMPLETE; otherwise overall is FAIL. downstream_model_allowed=false and live_execution_allowed=false in every outcome of this study.

STOP AND HONESTY RULES
Write REPORT regardless of outcome and never revise it. Do not call the public response an account snapshot, quote feed or execution-cost history. Do not transfer TenTrade/custom-symbol values into FTMO fields. Do not translate swap points into dollars without authentic tick economics and the applicable rollover multiplier. Do not use a test fixture or manually saved payload to pass the online provenance gate. Stop this acquisition if the official schema is malformed, ambiguous, redirects off the official domain, or contains secret-like keys. Any future correction or re-measurement uses a new artifact name and a new predeclared SPEC/GATE.
